# API Contracts

This file records active contracts between OFG systems. Historical migration details belong in archived plans or the active migration ExecPlan, not in current ownership claims.

## OFG-BOOT-001 TypeScript Host Ownership

TypeScript may own DOM boot, canvas lookup/creation, canvas resize policy, raw control-input event collection, fatal-error display, local dev ergonomics, WASM module loading, generic browser `fetch` for C++-requested opaque blob URIs, and Playwright smoke helpers. TypeScript must not parse glTF, choose animation poses, choose player model assets, own gameplay simulation, player movement, camera mode behavior, scene graph state, GPU pipeline creation, render draw submission, or game-world data structures.

## OFG-BOOT-002 C++ Runtime Ownership

C++ owns frame state, debug status, the current scene graph, stored raw control input, player movement behavior, camera mode behavior, demo-scene binding data, high-level renderer resources, blob request/cache state, resource-specific loading, render-object extraction, culling, draw-list construction, shadow settings, shadow cascade calculation, renderer/pass setup, WebGPU resource creation, browser WebGPU runtime behavior, model import/instantiation, and native Dawn offscreen rendering. OFG scene/game space is left-handed: `+X` is right, `+Y` is up, and `+Z` is forward for entity transforms, player movement, camera controls, camera-local forward, renderer-facing camera properties, and directional light entity forward. `Game`, `Resources`, `Renderer`, and renderer-internal `TempBuffer` are static lifecycle facades backed by one private singleton instance each for the active WebGPU device lifetime. Their public lifecycle is single-shot `create`, repeated preparation/frame calls as applicable, repeated `release` until done, and single-shot `destroy`. `Resources` owns active resource storage, queued/loading/loaded/failed blob entries, `ModelResource` objects, all durable imported mesh/material/texture/shader resources, a generic loading-resource scheduler, and the borrowed `GpuContext`; each `Resource` subtype owns its type-specific loading state machine behind `Resource::update_loading()`. `Renderer` owns explicit pass and target resources internally: an `RGBA16Float` scene-color target, a shared depth target, the cascaded shadow-map depth target, the shadow caster pass, the opaque pass, the procedural sky pass, the bloom pass, and the final tone-map pass. `ToneMapPass` always uses one bloom-capable pipeline shape, binding its durable 1x1 fallback bloom texture when no live bloom result is supplied. `TempBuffer` owns renderer-only reusable temporary render-target textures and views for post-effect scratch work; passes ask for exact descriptor matches with `TempBuffer::get(...)`, may return them with `TempBuffer::release(buffer)` after final encoded use, and otherwise rely on `TempBuffer::end_frame()`. `Game` owns the current `Scene` pointer, latest raw `ControlInput` snapshot, demo binding state, model-loading debug status, and the active scene passed into `Renderer::render`. The current `Scene` stores a root entity tree, entity local transforms, scene-owned `MeshRenderer`, `Player`, `AnimationPlayer`, `Camera`, and `Light` component containers, optional main-camera selection with first-camera fallback, and one scene-owned `Environment`. `Environment` owns ambient lighting, weather controls, deterministic day/night state, deterministic daylight/sunset/night/storm presets, moon/star state seeds, and a safe `Ptr<Light>` to the current main directional sun light; if that pointer is null during environment update, it scans scene lights and adopts the first directional light. `Scene::update` validates controls, updates `Environment`, updates players, updates animation players, updates CPU-skinned mesh renderers, then updates cameras. Future procedural override systems belong between animation-player updates and CPU skinning. Imported model data is C++ owned: glTF parsing produces OFG `ModelResource` templates with shared resource references, skin templates, skin vertex influences, and animation clips; model instantiation creates ordinary scene entities, binds clips through scene-owned `AnimationPlayer` components, and stores skinned model metadata as optional `SkinBinding` data on the relevant `MeshRenderer` rather than on standalone bone/joint components. The Quaternius browser player path is owned by the `Player` component: it requests the mesh GLB and UAL1 animation-library GLB through `Resources::load_model_resource`, polls `Ptr<ModelResource>` state, remaps `Idle_Loop`, `Walk_Loop`, and `Sprint_Loop` by node name to the player model after both resources load, attaches the model under the unscaled player entity, hides the fallback box renderer, and maps `Player::current_speed()` to idle/walk/sprint clip weights without applying root motion. `AnimationPlayer` owns weighted clip playback and pose blending for bound model entities. `Camera` owns control mode state for debug, first-person, and third-person behavior. `Renderer` resolves the selected scene camera into `CameraProperties`, extracts authored-visible mesh renderers into bounded transient render objects, camera-frustum culls those render objects into a private transient `DrawList`, records extracted/visible/culled culling diagnostics, builds a transient `LightProperties` list from `scene.environment().main_directional_light()` with direction from the light entity's world `+Z`, resolves ambient light from `scene.environment()`, builds three stable sun-shadow cascades, culls shadow casters from the full extracted render-object list per cascade, renders current-sun depth into a three-layer `Depth32Float` shadow-map target when shadows are enabled and above the low-sun fade cutoff, packs the cascade matrices and shadow sampling controls into the opaque pass shadow uniform, renders opaque content into the HDR scene-color target with shared depth while sampling the current sun shadow maps for direct-light attenuation, publishes public runtime shadow diagnostics, renders procedural sky into untouched far-depth pixels, ends the scene render pass, runs bloom from the completed HDR scene color into temporary targets, then tone-maps the scene color plus optional bloom into the platform target. Browser/native C++ frame drivers own platform target acquisition, command-buffer finish, and queue submit. The TypeScript host may call the narrow runtime facade, but it must not own scene graph state, player movement, camera behavior, renderer internals, resource objects, model resources, animation clips, animation players, skin bindings, draw commands, lighting state, shadow settings, shadow cascade calculation, shadow GPU resources, or GPU handles.

## OFG-BOOT-003 WASM Facade

The browser facade is narrow. TypeScript can create the runtime, resize it, pass one raw `ControlInput` snapshot per animation frame, poll generic blob-load requests, mark blob ids loading, complete or fail blob ids with opaque `Uint8Array` bytes, request a frame, read debug status, and dispose it. Browser disposal drains `Game::release()` synchronously, calls `Game::destroy()`, then releases browser WebGPU handles and the Embind wrapper. Debug status includes `modelLoadingState` and `playerModelLoaded` for model-load inspection, default demo-scene identity/count diagnostics, render-culling diagnostics, renderer resource counters, shadow pass diagnostics, bloom pass diagnostics, and temp-buffer memory/reuse diagnostics. The facade must not expose direct player-byte loading, raw renderer internals, GPU handles, camera pointers, player pointers, model resources, animation clips, skin bindings, mutable renderer settings, or mutable scene ownership to TypeScript.

## OFG-BOOT-004 Renderer Compatibility

Browser and native smoke must validate equivalent draw-list renderer behavior: the same tone-mapped procedural sky background with analytic atmosphere, sun, moon, procedural stars, and non-volumetric weather clouds, the same PBR-lit checker ground plane, the same saturated cube-color categories, the same fallback player box before model load or imported player model after browser model load, the same C++ resource layer and opaque PBR shader path, the same HDR scene-color plus final tone-map render path, the same current-sun shadow-depth pass and opaque shadow sampling when a sun exists, durable renderer resource creation outside ordinary frames, default demo-scene diagnostics, render-culling diagnostics, shadow pass diagnostics, active bloom diagnostics, temp-buffer reuse diagnostics, and reported adapter/backend/format diagnostics. Browser smoke uses Emdawnwebgpu and the browser's WebGPU implementation; native smoke uses an installed Dawn checkout through the same `webgpu.h` style renderer API. Their visual contract and smoke thresholds stay aligned through `tools/smoke-contract.json`.

## OFG-BOOT-005 WebGPU Baseline

The renderer must request no optional GPU features, must not manually request limits above the adapter defaults, and must record adapter/backend/format data in smoke reports. The current draw-list visual uses an opaque metallic-roughness PBR material path, a procedural sky pass, a bloom post effect, a perspective camera, depth buffering, one generated checker base-color texture, one generated white base-color texture, one neutral metallic-roughness texture, one flat normal texture, one scene-owned directional `Light` component selected by `Environment`, one `Environment` ambient light term, an expanded ground plane, a fallback player box or imported skinned player model, and the large default validation field of 150+ varied cube-mesh box instances used to exercise culling and shadow-cascade work. Directional light direction is not stored on the renderer; the renderer extracts the light travel direction from the selected light entity's world `+Z` into `LightProperties`. When a current sun exists, the renderer encodes depth-only caster draws into a durable three-layer `Depth32Float` texture array and samples that texture array from the opaque shader with a comparison sampler, three packed cascade matrices, receiver/normal bias, intensity, PCF mode/per-cascade radii, and cascade blend distances. This path uses ordinary render attachments, texture views, comparison sampler state, uniform buffers, and render pipelines only; no ray tracing or optional WebGPU features are requested. Opaque content renders first into an `RGBA16Float` linear scene-color texture with renderer-owned shared depth, applying shadow visibility only to direct sun lighting, then sky draws a fullscreen triangle at far depth only where opaque content did not write depth. Bloom samples that completed HDR scene color after the scene render pass has ended and before tone mapping. The sky shader combines analytic clear-sky radiance, sunrise/sunset horizon warmth, a tighter warm sun disc/core with restrained sky-side halo, a deterministic procedural starfield, moon disc/phase, and a cheap non-volumetric cloud layer driven by `SkyWeather` coverage, storm, haze, wind, opacity, and precipitation hints. A final tone-map pass composites bloom before exposure/ACES and writes fitted sRGB output into the browser or native platform target. Mesh vertices carry position, normal, tangent, and UV attributes for the PBR shader path. Debug counters must show durable renderer resources were created and must not assume exactly one pipeline once tone mapping, sky rendering, bloom rendering, shadow casting/sampling, multiple material bind-group layouts, or later variants exist. Surface or texture formats must be reported; native smoke uses `Rgba8Unorm`, and smoke background classification describes the tone-mapped sky output rather than direct byte-identical clear attachment writes.

## OFG-BOOT-006 Resource Lifetime

Texture, shader, material, mesh, pass, and pipeline resources must be created during initialization, preparation, first use for a changed scene/material combination, explicit resize, or explicit mutation, not every ordinary steady-state frame. Per-frame demo animation may rebuild draw commands and model matrices, but it must reuse the existing C++ resource objects. Shadow map texture arrays, cascade render/sampling views, comparison sampler state, shadow caster pipeline state, the opaque pass shadow uniform buffer, the opaque pass shadow bind-group layout, and the opaque pass fallback shadow texture/view/sampler are durable renderer resources; ordinary frames may redraw depth, update uniforms, and recreate only the opaque shadow bind group when the sampled shadow texture generation changes, but they must not recreate size-independent shadow resources unless a size, format, or pipeline-state setting changes. Renderer temp buffers are reusable WebGPU texture handles, not scene assets: `TempBuffer` may hand a returned buffer to later encoded work with the same descriptor, and only stale inactive buffers are destroyed during frame-boundary cleanup. `Resources::create_*` allocates and stores labeled high-level resources only; explicit resource `init_*` calls validate resource data and initialize GPU state. `Resources::load_blob` owns generic opaque byte requests and caches completed blob bytes by normalized relative URI until `Resources::release`; the browser host only services these requests and does not interpret the bytes. `Resource` is the common `Object` base for loadable resources with observable state and a virtual loading hook called by `Resources::advance_loads`; `ModelResource` inherits it and owns a temporary `ModelResourceLoader` while model loading is in progress. A normalized resource URI identifies one logical resource across the `Resources` registry; generated sub-resources use deterministic parent-URI `#` fragments so model roots, imported meshes, textures, materials, and shaders cannot collide. Loading the same URI twice returns the existing resource only when the requested resource type and load options match the original request; using the same URI with a different resource type or different load options is an `EngineError`, not a second cache entry. `Resources::load_model_resource` returns a stable `Ptr<ModelResource>` immediately, owns the target object, deduplicates by normalized URI, enqueues it in the generic loading scheduler, and leaves terminal loaded or failed resources owned until `Resources::release`. `ModelResourceLoader` owns the model-specific load state, discovers external glTF buffers/images through `Resources::load_blob`, imports into the same `ModelResource` object in place, and creates imported mesh/material/texture/shader resources through `Resources` using deterministic parent-URI `#` fragment labels for generated sub-resources. `Game::update` advances `Resources` loads after browser blob completions and before scene components observe resource state. Device-bound resource objects may store the borrowed `GpuContext` that created them so later mutation methods can refresh WebGPU state without a global device. Dynamic CPU-skinned meshes use `Mesh::init_dynamic_vertices` once per skinned renderer instance and `Mesh::update_vertices_in_place` for ordinary per-frame vertex writes; skinning may write existing vertex-buffer contents every frame, but it must not recreate vertex or index buffers during steady-state animation frames. Referenceable resources, entities, and components derive from `Object` and are non-copyable/non-movable while referenceable; owning containers such as `Resources` and `Scene` keep pointer-stable `std::unique_ptr` storage. Persistent non-owning references between `Object`-derived values use `Ptr<T>` when they can outlive an immediate stack borrow, so target destruction nulls observers and invalid access throws `EngineError`. Transient draw-list/render-extraction borrows may remain raw pointers because they are rebuilt and consumed inside one render operation. Resize reconfigures the surface only when physical width, physical height, or clamped device-pixel-ratio changes. Zero-size canvas axes must be preserved by the browser host so the C++ runtime can skip surface configuration and report a recoverable debug status instead of failing.

## OFG-BOOT-007 Generated Artifacts

`dist/`, `dist-test/`, `.deploy/`, `artifacts/`, and `assets/wasm/ofg_cpp/` are generated and ignored. `package-lock.json`, C++ source, TypeScript source, and toolchain version files are source-controlled.

## OFG-BOOT-008 Deployment

The default deployment target is Cloudflare Pages with build output directory `.deploy`. Packaged runtime files include the TypeScript app output, `assets/wasm/ofg_cpp/ofg_cpp.js` / `assets/wasm/ofg_cpp/ofg_cpp.wasm`, and the selected player model GLBs under `assets/models/player`. Local deployment uses `npm run deploy -- --project-name=ofg`, which packages the site and uploads through the Wrangler dependency pinned in `package-lock.json`. Workers static-assets deployment is documentation-only until a later plan adds `wrangler.jsonc` and Workers validation.

## OFG-BOOT-009 Coverage

Implementation files should meet 90% line coverage unless an exception is recorded in the active ExecPlan. C++ native-checkable code is covered by `npm run coverage:cpp`; TypeScript is covered by `npm run coverage:ts`. Browser-only C++ WebGPU glue and frame-driver submission are covered by `npm run build:wasm`, TypeScript adapter tests, and browser smoke. Native C++ Dawn rendering is covered by `npm run smoke:render`.
