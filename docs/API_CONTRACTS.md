# API Contracts

This file records active contracts between OFG systems. Historical migration details belong in archived plans or the active migration ExecPlan, not in current ownership claims.

## OFG-BOOT-001 TypeScript Host Ownership

TypeScript may own DOM boot, canvas lookup/creation, canvas resize policy, raw control-input event collection, raw debug-UI input event collection, debug-UI pointer-lock blocking based on C++ capture status, fatal-error display, local dev ergonomics, WASM module loading, generic browser `fetch` for C++-requested opaque blob URIs, and Playwright smoke helpers. TypeScript must not parse glTF, choose animation poses, choose player model assets, own gameplay simulation, player movement, camera mode behavior, scene graph state, Dear ImGui widget state, debug-variable storage, GPU pipeline creation, render draw submission, or game-world data structures.

## OFG-BOOT-002 C++ Runtime Ownership

C++ owns frame state, debug status, the `DebugMenu` debug-variable registry, `DebugBool` / `DebugInt` / `DebugFloat` scalar storage, the current scene graph, scene-owned terrain, stored raw control input, stored raw `DebugUiInput`, Dear ImGui input interpretation and capture wishes, player movement behavior, camera mode behavior, demo-scene binding data, high-level renderer resources, blob request/cache state, resource-specific loading, render-object extraction, culling, draw-list construction, shadow settings, shadow cascade calculation, renderer/pass setup, WebGPU resource creation, browser WebGPU runtime behavior, model import/instantiation, and native Dawn offscreen rendering. OFG scene/game space is left-handed: `+X` is right, `+Y` is up, and `+Z` is forward for entity transforms, player movement, camera controls, camera-local forward, renderer-facing camera properties, terrain height mapping to `+Y`, and directional light entity forward. `Game`, `Resources`, `Renderer`, and renderer-internal `TempBuffer` are static lifecycle facades backed by one private singleton instance each for the active WebGPU device lifetime. Their public lifecycle is single-shot `create`, repeated preparation/frame calls as applicable, repeated `release` until done, and single-shot `destroy`. `Resources` owns active resource storage, queued/loading/loaded/failed blob entries, `ModelResource` objects, all durable imported mesh/material/texture/shader resources, a generic loading-resource scheduler, and the borrowed `GpuContext`; each `Resource` subtype owns its type-specific loading state machine behind `Resource::update_loading()`. `Renderer` owns explicit pass and target resources internally: an `RGBA16Float` scene-color target, a shared depth target, the cascaded shadow-map depth target, the shadow caster pass, the opaque pass, the procedural sky pass, the bloom pass, the final tone-map pass, and the renderer-owned Dear ImGui `DebugUi` overlay. `DebugUi` owns the Dear ImGui context and upstream WebGPU backend for the active renderer lifetime, renders the cached `DebugMenu` tree into the final platform target after tone mapping, feeds `DebugUiInput` into ImGuiIO, and publishes dedicated debug UI diagnostics instead of contributing its upstream backend resources to the existing OFG renderer counters. `ToneMapPass` always uses one bloom-capable pipeline shape, binding its durable 1x1 fallback bloom texture when no live bloom result is supplied. `TempBuffer` owns renderer-only reusable temporary render-target textures and views for post-effect scratch work; passes ask for exact descriptor matches with `TempBuffer::get(...)`, may return them with `TempBuffer::release(buffer)` after final encoded use, and otherwise rely on `TempBuffer::end_frame()`. `Game` owns the current `Scene` pointer, latest raw `ControlInput` snapshot, latest raw `DebugUiInput` snapshot, demo binding state, model-loading debug status, the latest debug UI frame info passed into `Renderer::render`, and the active scene passed into `Renderer::render`. The current `Scene` stores a root entity tree, entity local transforms, scene-owned `MeshRenderer`, `Player`, `AnimationPlayer`, `Camera`, and `Light` component containers, optional main-camera selection with first-camera fallback, one scene-owned `Environment`, and one scene-owned `Terrain`. `Environment` owns ambient lighting, weather controls, deterministic day/night state, deterministic daylight/sunset/night/storm presets, moon/star state seeds, and a safe `Ptr<Light>` to the current main directional sun light; if that pointer is null during environment update, it scans scene lights and adopts the first directional light. `Terrain` owns deterministic `TerrainConfig`, world-coordinate sampling, the fixed LOD0 chunk constants, a map of currently streamed `TerrainChunk` objects keyed by `(LOD, X, Y, Z)`, and origin-centred ticking that reconciles a 5 by 5 LOD0 surface region around the primary player or origin by unloading unwanted chunks and creating missing chunks. `TerrainChunk` owns generated 33 by 33 LOD0 surface height samples and later terrain render-resource references for that same chunk identity. `Scene::update` validates controls, updates `Environment`, updates players, updates animation players, ticks `Terrain` after player movement using the primary player position when available, updates CPU-skinned mesh renderers, then updates cameras. Imported model data is C++ owned: glTF parsing produces OFG `ModelResource` templates with shared resource references, skin templates, skin vertex influences, and animation clips; model instantiation creates ordinary scene entities, binds clips through scene-owned `AnimationPlayer` components, and stores skinned model metadata as optional `SkinBinding` data on the relevant `MeshRenderer` rather than on standalone bone/joint components. The Quaternius browser player path is owned by the `Player` component: it requests the mesh GLB and UAL1 animation-library GLB through `Resources::load_model_resource`, polls `Ptr<ModelResource>` state, remaps `Idle_Loop`, `Walk_Loop`, and `Sprint_Loop` by node name to the player model after both resources load, attaches the model under the unscaled player entity, hides the fallback box renderer, and maps `Player::current_speed()` to idle/walk/sprint clip weights without applying root motion. `AnimationPlayer` owns weighted clip playback and pose blending for bound model entities. `Camera` owns control mode state for debug, first-person, and third-person behavior. `Renderer` resolves the selected scene camera into `CameraProperties`, extracts authored-visible mesh renderers into bounded transient render objects, camera-frustum culls those render objects into a private transient `DrawList`, records extracted/visible/culled culling diagnostics, builds a transient `LightProperties` list from `scene.environment().main_directional_light()` with direction from the light entity's world `+Z`, resolves ambient light from `scene.environment()`, builds three stable sun-shadow cascades, culls shadow casters from the full extracted render-object list per cascade, renders current-sun depth into a three-layer `Depth32Float` shadow-map target when shadows are enabled and above the low-sun fade cutoff, packs the cascade matrices and shadow sampling controls into the opaque pass shadow uniform, renders opaque content into the HDR scene-color target with shared depth while sampling the current sun shadow maps for direct-light attenuation, publishes public runtime shadow diagnostics, renders procedural sky into untouched far-depth pixels, ends the scene render pass, runs bloom from the completed HDR scene color into temporary targets, tone-maps the scene color plus optional bloom into the platform target, and finally renders the Dear ImGui debug overlay into that same platform target with load/store. `Game` masks gameplay control input before `Scene::update` when the previous ImGui frame reported mouse or keyboard capture. Browser/native C++ frame drivers own platform target acquisition, command-buffer finish, and queue submit. The TypeScript host may call the narrow runtime facade, but it must not own scene graph state, terrain generation, terrain chunks, player movement, camera behavior, renderer internals, resource objects, model resources, animation clips, animation players, skin bindings, debug-variable storage, Dear ImGui widget state, draw commands, lighting state, shadow settings, shadow cascade calculation, shadow GPU resources, or GPU handles.

## OFG-BOOT-003 WASM Facade

The browser facade is narrow. TypeScript can create the runtime, resize it, pass one raw `ControlInput` snapshot per animation frame, pass one raw `DebugUiInput` snapshot per animation frame, poll generic blob-load requests, mark blob ids loading, complete or fail blob ids with opaque `Uint8Array` bytes, request a frame, read debug status, and dispose it. `ControlInput` carries gameplay/camera movement and remaining gameplay debug edges; the shadow-map preview is intentionally not a `ControlInput` or renderer-setter field and is controlled by the C++ `DebugMenu` bool path `render/shadows/show_debug_overlay`. Browser disposal drains `Game::release()` synchronously, calls `Game::destroy()`, then releases browser WebGPU handles and the Embind wrapper. `DebugUiInput` is a browser-event snapshot containing focus, pointer-lock state, canvas CSS-pixel mouse position, mouse button bitset, wheel deltas, F1 visibility toggle edge, DOM `KeyboardEvent.code` arrays for current/pressed/released keys, and UTF-8 text input. Debug status includes `modelLoadingState` and `playerModelLoaded` for model-load inspection, default demo-scene identity/count diagnostics, render-culling diagnostics, renderer resource counters, shadow pass diagnostics, renderer-owned Dear ImGui `debugUi` diagnostics, bloom pass diagnostics, and temp-buffer memory/reuse diagnostics. `debugUi` reports visibility, ImGui capture wishes, overlay pass count, cached menu tree generation/rebuild count, draw-list and draw-command counts, vertex/index counts, estimated uploaded vertex/index bytes, estimated vertex/index buffer capacity, estimated buffer growth counts, and observed font texture creation. The facade must not expose direct player-byte loading, raw renderer internals, GPU handles, camera pointers, player pointers, model resources, animation clips, skin bindings, mutable renderer settings, mutable debug-variable pointers, Dear ImGui pointers, or mutable scene ownership to TypeScript.

## OFG-BOOT-004 Renderer Compatibility

Browser and native smoke must validate equivalent draw-list renderer behavior: the same tone-mapped procedural sky background with analytic atmosphere, sun, moon, procedural stars, and non-volumetric weather clouds, the same scene-owned terrain surface rendered as addressable chunk debug planes during the first terrain milestone, the same saturated cube-color categories, the same fallback player box before model load or imported player model after browser model load, the same C++ resource layer and opaque draw-list shader/material path, the same HDR scene-color plus final tone-map render path, the same current-sun shadow-depth pass and opaque shadow sampling when a sun exists, the same renderer-owned Dear ImGui debug overlay after tone mapping, durable renderer resource creation outside ordinary frames, default demo-scene diagnostics, render-culling diagnostics, shadow pass diagnostics, debug UI diagnostics, active bloom diagnostics, temp-buffer reuse diagnostics, and reported adapter/backend/format diagnostics. Browser smoke uses Emdawnwebgpu and the browser's WebGPU implementation; native smoke uses an installed Dawn checkout through the same `webgpu.h` style renderer API. Their visual contract and smoke thresholds stay aligned through `tools/smoke-contract.json`; the existing `groundPixels` report field now means authored terrain/ground surface coverage and accepts the red/green height-debug terrain output. Scene-pixel smoke ignores the known left debug-UI column so the visible overlay does not count as world pixels; separate `debugUi` status assertions prove the overlay pass, draw data, upload estimates, and font texture path.

## OFG-BOOT-005 WebGPU Baseline

The renderer must request no optional GPU features, must not manually request limits above the adapter defaults, and must record adapter/backend/format data in smoke reports. The current draw-list visual uses an opaque metallic-roughness PBR material path for non-terrain demo objects, a terrain height-debug shader path for flat LOD0 chunk planes, a procedural sky pass, a bloom post effect, a perspective camera, depth buffering, one generated white base-color texture, one neutral metallic-roughness texture, one flat normal texture, one scene-owned directional `Light` component selected by `Environment`, one `Environment` ambient light term, a 5 by 5 set of scene-owned terrain debug planes using `R16Float` heightfield textures, a fallback player box or imported skinned player model, and the large default validation field of 150+ varied cube-mesh box instances used to exercise culling and shadow-cascade work. Directional light direction is not stored on the renderer; the renderer extracts the light travel direction from the selected light entity's world `+Z` into `LightProperties`. When a current sun exists, the renderer encodes depth-only caster draws into a durable three-layer `Depth32Float` texture array and samples that texture array from the opaque shader with a comparison sampler, three packed cascade matrices, receiver/normal bias, intensity, PCF mode/per-cascade radii, and cascade blend distances. This path uses ordinary render attachments, texture views, comparison sampler state, uniform buffers, and render pipelines only; no ray tracing or optional WebGPU features are requested. Opaque content renders first into an `RGBA16Float` linear scene-color texture with renderer-owned shared depth, applying shadow visibility only to direct sun lighting, then sky draws a fullscreen triangle at far depth only where opaque content did not write depth. Bloom samples that completed HDR scene color after the scene render pass has ended and before tone mapping. The sky shader combines analytic clear-sky radiance, sunrise/sunset horizon warmth, a tighter warm sun disc/core with restrained sky-side halo, a deterministic procedural starfield, moon disc/phase, and a cheap non-volumetric cloud layer driven by `SkyWeather` coverage, storm, haze, wind, opacity, and precipitation hints. A final tone-map pass composites bloom before exposure/ACES and writes fitted sRGB output into the browser or native platform target. Mesh vertices carry position, normal, tangent, and UV attributes for the PBR shader path and the terrain debug shader consumes the same vertex layout. Debug counters must show durable renderer resources were created and must not assume exactly one pipeline once tone mapping, sky rendering, bloom rendering, shadow casting/sampling, multiple material bind-group layouts, or later variants exist. Surface or texture formats must be reported; native smoke uses `Rgba8Unorm`, and smoke background classification describes the tone-mapped sky output rather than direct byte-identical clear attachment writes.

## OFG-BOOT-006 Resource Lifetime

Texture, shader, material, mesh, pass, and pipeline resources must be created during initialization, preparation, first use for a changed scene/material combination, explicit resize, or explicit mutation, not every ordinary steady-state frame. Compatible material bind-group layouts are shared by structural material binding layout so many materials with different textures do not force one pipeline per material instance. The opaque pass starts with a bounded 256-draw uniform capacity for the default terrain/debug scene, and ordinary camera or mode exercises must not grow that draw-uniform buffer after warmup. Per-frame demo animation may rebuild draw commands and model matrices, but it must reuse the existing C++ resource objects. Shadow map texture arrays, cascade render/sampling views, comparison sampler state, shadow caster pipeline state, the opaque pass shadow uniform buffer, the opaque pass shadow bind-group layout, and the opaque pass fallback shadow texture/view/sampler are durable renderer resources; ordinary frames may redraw depth, update uniforms, and recreate only the opaque shadow bind group when the sampled shadow texture generation changes, but they must not recreate size-independent shadow resources unless a size, format, or pipeline-state setting changes. Dear ImGui context/backend setup belongs to the renderer preparation lifecycle, and `DebugUi` must shut down the ImGui WebGPU backend and destroy the ImGui context during renderer release before the borrowed GPU context is cleared. Ordinary frames may let the upstream ImGui backend grow vertex/index buffers, update uploaded vertex/index contents, and create/update the font texture as ImGui requires, but they must not recreate the ImGui context or backend every frame. Renderer temp buffers are reusable WebGPU texture handles, not scene assets: `TempBuffer` may hand a returned buffer to later encoded work with the same descriptor, and only stale inactive buffers are destroyed during frame-boundary cleanup. `Resources::create_*` allocates and stores labeled high-level resources only; explicit resource `init_*` calls validate resource data and initialize GPU state. `Resources::load_blob` owns generic opaque byte requests and caches completed blob bytes by normalized relative URI until `Resources::release`; the browser host only services these requests and does not interpret the bytes. `Resource` is the common `Object` base for loadable resources with observable state and a virtual loading hook called by `Resources::advance_loads`; `ModelResource` inherits it and owns a temporary `ModelResourceLoader` while model loading is in progress. A normalized resource URI identifies one logical resource across the `Resources` registry; generated sub-resources use deterministic parent-URI `#` fragments so model roots, imported meshes, textures, materials, and shaders cannot collide. Loading the same URI twice returns the existing resource only when the requested resource type and load options match the original request; using the same URI with a different resource type or different load options is an `EngineError`, not a second cache entry. `Resources::load_model_resource` returns a stable `Ptr<ModelResource>` immediately, owns the target object, deduplicates by normalized URI, enqueues it in the generic loading scheduler, and leaves terminal loaded or failed resources owned until `Resources::release`. `ModelResourceLoader` owns the model-specific load state, discovers external glTF buffers/images through `Resources::load_blob`, imports into the same `ModelResource` object in place, and creates imported mesh/material/texture/shader resources through `Resources` using deterministic parent-URI `#` fragment labels for generated sub-resources. `Game::update` advances `Resources` loads after browser blob completions and before scene components observe resource state. Device-bound resource objects may store the borrowed `GpuContext` that created them so later mutation methods can refresh WebGPU state without a global device. Dynamic CPU-skinned meshes use `Mesh::init_dynamic_vertices` once per skinned renderer instance and `Mesh::update_vertices_in_place` for ordinary per-frame vertex writes; skinning may write existing vertex-buffer contents every frame, but it must not recreate vertex or index buffers during steady-state animation frames. Referenceable resources, entities, and components derive from `Object` and are non-copyable/non-movable while referenceable; owning containers such as `Resources` and `Scene` keep pointer-stable `std::unique_ptr` storage. Persistent non-owning references between `Object`-derived values use `Ptr<T>` when they can outlive an immediate stack borrow, so target destruction nulls observers and invalid access throws `EngineError`. Transient draw-list/render-extraction borrows may remain raw pointers because they are rebuilt and consumed inside one render operation. Resize reconfigures the surface only when physical width, physical height, or clamped device-pixel-ratio changes. Zero-size canvas axes must be preserved by the browser host so the C++ runtime can skip surface configuration and report a recoverable debug status instead of failing.

## OFG-BOOT-007 Generated Artifacts

`dist/`, `dist-test/`, `.deploy/`, `artifacts/`, and `assets/wasm/ofg_cpp/` are generated and ignored. `package-lock.json`, C++ source, TypeScript source, and toolchain version files are source-controlled.

## OFG-BOOT-008 Deployment

The default deployment target is Cloudflare Pages with build output directory `.deploy`. Packaged runtime files include the TypeScript app output, `assets/wasm/ofg_cpp/ofg_cpp.js` / `assets/wasm/ofg_cpp/ofg_cpp.wasm`, and the selected player model GLBs under `assets/models/player`. Local deployment uses `npm run deploy -- --project-name=ofg`, which packages the site and uploads through the Wrangler dependency pinned in `package-lock.json`. Workers static-assets deployment is documentation-only until a later plan adds `wrangler.jsonc` and Workers validation.

## OFG-BOOT-009 Coverage

Implementation files should meet 90% line coverage unless an exception is recorded in the active ExecPlan. C++ native-checkable code is covered by `npm run coverage:cpp`; TypeScript is covered by `npm run coverage:ts`. Browser-only C++ WebGPU glue and frame-driver submission are covered by `npm run build:wasm`, TypeScript adapter tests, and browser smoke. Native C++ Dawn rendering is covered by `npm run smoke:render`.
